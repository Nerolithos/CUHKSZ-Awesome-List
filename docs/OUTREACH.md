# Developer outreach / 联系开发者

For posting in another repository’s GitHub Discussions, use the [repository-specific bilingual discussion drafts](DISCUSSION_INVITATION.md). / 在他人仓库的 GitHub Discussions 留言时，可使用[逐仓库中英文邀请文案](DISCUSSION_INVITATION.md)。

## Should you contact authors? / 是否需要联系？

English: A brief, accurate link listing is an editorial decision; do not describe it as an endorsement or demand permission to copy code. A personal invitation is useful for checking descriptions, license status, maintenance expectations, and additional submissions. Obtain explicit permission before reproducing assets, adding a personal profile, or naming an author as a maintainer. No author has been contacted by this repository’s initial preparation.

中文：简短、准确地收录公开链接是编辑行为，不要宣传成作者背书，也不要把收录链接混同于复制代码。个人邀请适合用来核对描述、许可和维护状态，并邀请补充项目。转载素材、收录个人主页或将作者列为维护者前，要取得明确同意。本仓库首版准备过程中未联系任何作者。

## Where and how / 渠道与节奏

1. Follow the project’s published contact preferences. Prefer a public maintainer email, a community discussion category that permits introductions, or an existing campus contact. Do not invent email addresses from student numbers. / 优先遵循项目公开联系偏好，使用维护者主动公开的邮箱、允许介绍项目的讨论区或已有校园联系，不根据学号猜测邮箱。
2. Contact a lab once for its related projects. Make each message specific and brief. Use an issue only when its guidelines permit community questions; do not file promotional bug reports. / 同一实验室的项目合并联系一次，简短而具体；仅在规则允许时使用 Issue，不把推广包装成 Bug。
3. Ask for a description check, a preferred project link, and optional contributions. Make adding a license a separate, optional request; never prescribe a license over third-party content. / 请求核对描述、推荐入口及自愿贡献；补充许可是独立且可选的请求，不替第三方材料指定许可。
4. Do not request stars, follows, reciprocal links, or official endorsement. Send at most one polite follow-up after 7–14 days, then stop. Silence is not consent. / 不索要 Star、关注、互链或官方背书；7–14 天后最多礼貌跟进一次，之后停止，沉默不代表同意。

## Tracking / 跟踪

Record only project, date, channel type, response status, and requested editorial changes. Keep private email addresses and correspondence out of public commits. Never label someone a contributor or maintainer without agreement. Choose the relevant draft before sending. / 仅记录项目、日期、渠道类型、回复状态及编辑请求；私人邮箱和通信不进入公开提交。未经同意，不将对方列为贡献者或维护者。发送前选择对应项目的文案。
